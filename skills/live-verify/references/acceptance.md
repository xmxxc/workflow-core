# 环境准备与现场验收

进入现场验收或修复回归时读取本文件；准备发布结果和判断原票关闭时读取 [验收工作记录](work-records.md) 的验收部分。

## 环境就绪与验收清单

部署或切换版本之前，逐项执行放行交接里的部署前门禁，把命令、对象和结果写进本轮报告；任何一项不满足、无法访问或对象不明确时，停止部署并交回总控。

按项目已有部署/启动方式准备环境，复用已获授权的操作；需要用户执行的登录、重启或现场动作给出可直接使用的步骤。只操作已确认的环境；迁移、停机、数据影响等按实际项目选择备份和恢复办法，保留本地修改，不把 SQLite 或某一种重启命令作为通用前提。

记录环境实际运行版本、相关配置和日志/事件游标；区分已合并、已部署与正在运行。确认启动或健康基线，再读本轮新增证据。只有实际命令和日志支持时才宣称版本已生效。

首次建立清单时逐项阅读本批 PR 非测试改动、需求和相关文档；修复回归时读取变化部分与关联影响，并核对旧清单仍覆盖当前行为，为每个用户可见的新行为列操作入口与预期结果。预期来自需求和契约，而非当前实现；源码用于核对实际命令格式与前置。各项分类：

- **现在可验收**：有可达入口、环境和必要权限。
- **未到时机/受阻**：记录依赖、解除条件、是否影响原票完成，并留在 issue。
- **无需真实环境验收**：说明原因与已有验证；纯文档等可由总控按授权关闭。

完成条件：所有本轮行为有分类，环境版本和前置可核对；必需项受阻时不宣称整票完成。

## 分轮主持

先给简短轮次概览，按依赖和用户可操作量展开当前一轮，环境恢复或健康基线先行。每一步写明谁操作、可复制动作、预期可见结果与必要前置；真实凭据只走项目约定的安全入口，示例使用假数据。

给完当前轮次后等待用户反馈，读取该轮之后的日志、事件或状态证据，再逐项判定：**通过**、**按契约的预期限制**、**未执行**、**偏差**。缺少日志不证明操作未执行：先核对证据覆盖和用户反馈，缺口写未确认，再补必要步骤。平台限制需与约定行为相符，不能把未满足需求解释成通过。

发现偏差时记录复现和已确认的事实；可只读定位代码，根因未明写待诊断。先判断偏差属于哪一类，它决定原票的标签和去向（见 [工作记录](work-records.md) 的标签表）：本票需求在真机上不成立；与本票完成条件无关的新问题；环境或平台受阻、无法判定。按 tracker 与已有授权新建或更新同类问题票，关联原票和去敏证据；用户将入口交回总控安排修复。阻塞后续时暂停受影响步骤，其余独立项可继续。修复后核对新版本、必要审查与本轮授权，再回归原失败行为。

# 真实环境验收

你长期维护现场验收上下文：接收总控放行的 PR，按授权合并，带用户逐轮操作，自己读取证据、判断行为，并在每张原票留下结果。开发总控负责代码和审查，两条线通过用户交接；发现代码问题时交回总控安排修复。

## 接管与换会话

1. 读取项目指令和 `docs/agents/` 下的 tracker、标签和领域约定。项目未初始化时，先调用 `setup-matt-pocock-skills` 并完成它原有的交互。
2. 读取已有的真实环境档案。没有档案时，再读 [项目档案模板](references/project-profile.md)，在 `docs/agents/live-verify.md` 按需建立。先查配置和源码，只向用户问真正的缺口。
3. 找到总控账本：`docs/agents/work/ai-coding/<范围>/`，旧项目也可能在 `docs/agents/work/<阶段>/`。读取 `state.md` 和放行交接。自己的计划和报告写成 `prompts/`、`reports/` 下的具名轮次文件；`state.md` 由总控维护。

接管时记下本会话的标识。新会话接手时（清空上下文、压缩后续接、换 agent 或换宿主），先读档案、最近一轮报告、原 Issue/PR 和实际运行版本，然后在本轮报告写一行“由 <会话标识> 接手，起点 <最近报告或状态>”。

沿用已有的操作授权；用户交接代码放行，并不自动授予生产部署、迁移、真实登录或清理数据的权限。按当前宿主实际可用的工具和权限操作；缺少能力时，给出具体缺口和用户可以操作的入口。

## 按阶段推进

- **收到批次或 PR 号码**：读取 [接收与合并](references/merge.md)。
- **环境准备与现场操作**：读取 [环境与验收](references/acceptance.md)。
- **发布结果、切换标签与收尾**：读取 [工作记录](references/work-records.md)。

原票的承诺仍不成立，或必需行为还没验证时，原票保持打开；即使已经另开了问题票也一样。回归通过后，才按授权关闭。额外改进另开票跟进，不阻塞已经满足自身条件的原票。

## 交付

本范围完成的条件：每张原票都有合并记录、实际运行版本和验收结论；标签与结论一致；未覆盖和受阻项都写明解除条件；报告和 Issue 留痕已回读确认；下一负责人已明确。

每轮交付：实际合并与运行版本、已验收范围、未覆盖与受阻项、后续票、每张原票的标签与状态及理由、残留测试数据，以及下一负责人。报告路径交给用户，由用户转给总控。

浏览器和网页抓取类专项工具（如 Playwright、Firecrawl）只在用户明确选择时使用；用户可以直接在实际产品、设备、后台或终端中操作。

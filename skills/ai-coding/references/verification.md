# 验证分层与测试矩阵

在实施、修复、独立审查或准备放行时，需要选择测试范围、判断是否触发矩阵或复用已有证据时读取本文件。验证范围按候选变化、项目规则和风险选择；完整审查覆盖完整差异，不自动等于完整测试套件。

## 验证等级

| 等级 | 目的 | 默认时机 |
| --- | --- | --- |
| `fast` | 格式、静态检查、类型/编译检查和直接单元测试 | 代码、配置、构建或行为变化时 |
| `focused` | 受影响模块、失败回归、一个正常控制路径和直接依赖 | 行为变化或审查发现需要回归时 |
| `integration` | 跨模块、服务、构建产物、迁移或真实协议边界 | 共享契约或跨边界变化时 |
| `full-ci` | 精确候选的项目全量 CI 或等价完整检查 | 最终候选；候选 head 变化后重新固定 |
| `matrix` | 一组明确维度的组合、变异、兼容性或竞态验证 | 触发条件满足时 |

等级是语言无关的。具体命令从项目规则、CI、构建配置和包管理配置中发现；不要在本入口硬编码某种语言的工具名称。

## 矩阵触发

矩阵按被验证的契约触发，而不是按“增量审查”或“完整审查”这两个名称触发。任务入口或项目报告应为每个矩阵写出 `id`、维度、输入和触发条件。常见触发包括：

- CI、资产拼装、构建脚本或分支组合变化：源码树、依赖树、构建产物和发布组合矩阵；
- 平台、编译器、架构、ABI 或运行时版本变化：兼容性矩阵；
- 权限、协议、状态机、并发、恢复或跨进程变化：角色、状态、竞态和错误回执矩阵；
- UI 路由、渲染或端到端契约变化：浏览器、设备、路由和构建产物矩阵；
- 数据库、序列化或迁移变化：空库、旧库、升级路径和回滚矩阵。

没有触发条件的历史矩阵作为已保存证据引用，不在每轮审查机械重跑。共享框架、核心契约、依赖锁文件、CI 配置、资产 SHA 或矩阵输入变化时重新判断；无法界定影响时扩大到 `integration` 或 `matrix`，并记录扩大理由。

## 阶段选择

- 实施或修复：代码、配置、构建或行为变化完成 `fast`；行为变化完成 `focused`；纯文档或说明变化只运行项目要求的文档检查，没有对应检查时不启动代码测试；只有跨边界变化才增加 `integration` 或相关 `matrix`。
- 增量复核：验证新增补丁、失败回归、正常控制和受影响调用链；矩阵只在本轮触发条件满足时执行。
- 首次完整审查：审查完整差异，运行需求相关的 `focused`/`integration`，并判断是否需要矩阵。
- 最终完整审查和放行：审查 PR 基线到最终候选的完整差异，取得精确 head 的 `full-ci`，执行仍被触发的矩阵，复用未变输入对应的历史证据。
- 真实验收：交付固定候选、CI、矩阵证据和限制；真实平台操作由验收长线主持。

精确候选的 CI 结果可以作为 Standards 和 Spec 两轴的共同验证证据。独立审查任务内的昂贵验证由一个明确的验证步骤归属并保存日志，两个轴消费同一固定快照和结果；需要重跑时以失败诊断、环境变化或候选变化为理由。

## 证据复用与回报

矩阵或全量证据至少绑定：

`repo + PR/目标 + base + merge-base + head + tree + 依赖/资产输入 + matrix id`

候选只改变与矩阵无关的文件时，可保留该矩阵并重新执行受影响的 `focused` 检查。rebase、force-push、CI/构建配置、依赖锁、资产输入或相关契约变化时，旧证据只覆盖旧对象，先重新判断覆盖范围。

报告记录：验证等级、矩阵 `id`、触发依据、实际命令或 CI 入口、候选身份、通过/失败/跳过数、复用的固定证据、环境限制和下一动作。作者自查、独立审查和真实验收分别记录，不能互相替代。

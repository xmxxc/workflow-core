# 人工转交

你写任务文件，用户把它交给执行者或审查者，再把结果带回。你不创建、发送、等待或续接 agent。

## 交给用户

- 每个任务文件给一句启动语：`请读取并执行 <绝对路径>，完成后把回报文件路径和 PR/Issue 留痕链接带回。`
- 一次给出多个任务时，合并成一条消息逐项列出，并标明哪些必须交给不同的执行上下文：同一候选的实施和审查，不能落在同一个上下文里。
- 确认提示词、项目规则、固定候选和回报位置，接收者都能按绝对路径读到。

## 状态证据

把任务文件交给用户之后，记为 `pending-handoff`。接收者写下接手评论或回报了会话标识，记为 `accepted`。回报文件存在、要求的留痕也回读确认之后，记为 `returned`。用户说“已转交”，只能证明 `pending-handoff`。

## 独立性

接收者回报自己的会话或任务标识；你核对它与所有作者都不同，并且只读固定快照。接收方 agent 为每个任务新开、带独立标识、且没有参与写该候选的子会话，可以当作独立审查者。共享作者上下文的子会话不能当作独立审查者。

## worker 的授权

人工模式下，worker 默认没有任何外部动作授权；每个任务文件的“授权”一行写明本轮允许的提交、推送、PR 和评论动作。

## 中断

用户长时间没带回结果时，任务保持 `pending-handoff` 或 `accepted`，不写成完成；失效的判定和改派按 [账本](../references/ledger.md) 处理。提示词路径或回报入口失效时，保留现场，更新入口和下一动作。

# 宿主独立任务

你通过当前宿主实际暴露的独立会话或任务接口，直接派发、等待和回收 worker 与审查者。

## 能力核对

首次派发、恢复或通信异常时，按当前宿主实际的工具和 schema，分别核对 create、send、read、wait、resume/wake 和 independent-context，记成本轮的能力记录：接口、实际任务标识、发送回执、可读状态或结果、等待方式、续接结果、上下文隔离证据和限制。这是调度能力记录，不是测试矩阵。产品名、模型名、窗口标题或任务名都不能证明能力。

创建成功只证明对象已入队；入队不证明已执行，启动不证明会自动唤醒，一个宿主的结果也不证明其他宿主有同样能力。

## 派发与回收

- 外层实施和审查各用独立的会话或任务。宿主只能提供共享上下文的子 agent 时，不把它记作独立审查者：记录能力缺口，并阻塞最终放行。技能单元内部已有的子 agent 委派，按其原规则执行。
- 发送时指定可读的任务文件、项目根、分支/工作树、固定候选和回报路径，长约束放在任务文件里；保存任务标识、发送回执和读取游标。
- 超时或报错时，先查询已有对象，确认是否已经创建或发送，避免重复派发。
- 只管理本轮创建的任务；任务结束、工作已保存后，再归档或清理。
- 局部失败只阻塞受影响的票和依赖，其他就绪票继续。
- 通信能力不足时，保留现场和下一动作。本模式不静默退回共享子 agent 或人工转交；要换模式，由用户决定。

## worker 的授权

用户以本模式调用并指定仓库和范围，即授权 worker 提交自有任务分支、推送、创建或更新 PR，以及发必要的 Issue/PR 评论。生产操作、正式合并和其他仓库的操作，仍按已有授权处理。

## 持续机制

宿主有 Goal 或其他原生持续机制时，先查当前目标：同范围、同终点的复用；不一致时保留事实，说明需要用户做什么决定，不覆盖无关目标。用户没指定预算就不设预算；宿主要求明确的创建请求而当前委托不够时，报告缺少的授权。

没有持续机制时，在当前运行内派发、等待和回收；区分同轮等待、用户显式续接和原生自动续跑。需要跨轮而又没有自动续接时，报告能力阻塞，留下恢复入口。不保证终端关闭、服务停止或休眠之后还能继续。

用户手动暂停是合法状态：记录暂停者、时间、原因和恢复入口；暂停期间不派发新任务。用户后续的输入视为对当前目标的纠正，除非用户明确取消或替换。额度不足、服务故障或外部决定未解决时，不写成完成。

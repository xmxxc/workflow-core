# Codex 独立线程

本模式只在 Codex 宿主中使用，宿主需要提供独立任务接口。下文约束本模式的派发、等待和独立性证据。

## 独立任务要求

外层 worker 和审查者必须通过宿主提供的独立任务接口创建为 Codex 可单独查看、回读和续接的任务。创建后先回读实际任务 ID 和状态，再继续派发；`collaboration.spawn_agent`、`fork_turns:none` 或仅有不同窗口标题的子 agent 不能作为本入口的独立任务证据。宿主没有合格独立任务接口时，保留任务文件和现场并报告能力阻塞，不改用外层子 agent 冒充独立执行。

## 运行时能力

首次派发、恢复持续任务或通信异常时读取本文件。使用当前宿主实际暴露的工具与 schema，分别核对：create、send、read、wait、resume/wake 和 independent-context。产品名、模型名、窗口标题或任务名称都不能证明能力。

为本轮记录能力矩阵：工具/接口、实际任务标识、发送回执、可读状态或结果、等待方式、续接结果、上下文隔离证据和限制。这里的“能力矩阵”是调度能力记录，不是测试矩阵；测试等级、矩阵触发和证据复用按 [验证分层与测试矩阵](../references/verification.md) 处理。创建成功只证明对象入队；入队不证明已经执行，启动不证明已经自动唤醒，某一宿主的结果也不证明其他宿主具备同样能力。

外层实施与审查必须使用宿主实际提供的独立任务接口，任务应有可单独读取、发送续接消息和等待的任务 ID。对于本入口，优先使用 Codex 的 `create_thread`、`read_thread`、`send_message_to_thread` 和 `wait_threads`；调用成功后回读任务对象确认其状态和独立上下文。若宿主只能提供共享上下文的子 agent，不能把它记作外层独立审查者；`collaboration.spawn_agent` 或 `fork_turns:none` 不满足本入口要求。记录能力缺口并阻塞最终放行。Matt 单元内部已有的子 agent 委派遵循其原规则。

发送任务时指定实际可读的任务文件、项目根、分支/工作树、固定候选和回报路径，把长约束放入任务文件；保存任务 ID、发送回执和读取游标。文件存在、任务标题、窗口出现或中途消息都不等于已经执行或完成；先取状态、候选版本、结论/阻塞和报告入口，再按需展开细节。超时或错误先查询已有对象，确认是否已创建或发送，避免重复派发。只管理本轮创建的任务；任务结束、工作保存后再归档或清理。局部失败只阻塞受影响票及依赖，其他就绪票继续。通信能力不足时保留现场和下一动作；全 AI 模式不静默退回外层子 agent 或人工派发。

有 Goal 或其他原生持续机制时，先查当前目标；同范围同终点复用，不一致时保留事实并说明需要的决定，不覆盖无关目标。用户未指定预算就不擅设预算；宿主要求明确创建请求而当前委托不足时报告所缺授权。只有在当前宿主实际可用并记录证据后才使用。没有持续机制时，继续在当前有效运行内派发、等待和回收；区分同轮等待、用户显式续接和原生自动续跑；需要跨轮而无自动续接时报告能力阻塞，留下恢复入口。不保证终端关闭、服务停止或休眠后的继续。续跑或用户恢复时重新核对状态、候选版本和用户最新范围，不从上一句推断完成。

用户手动暂停是合法的运行状态，应记录暂停者、时间、原因和恢复入口；它不等同于阻塞、取消或完成。暂停期间不派发新任务，恢复时先按 [账本](../references/ledger.md) 回读权威状态。用户后续输入视为当前目标的纠正，除非明确取消或替换。Goal 状态、暂停、阻塞、预算和完成按宿主规范处理；不能因额度、服务故障或外部决定未解决而写成完成。

## worker 的授权

用户以本模式调用并指定仓库和范围，即授权 worker 提交自有任务分支、推送、创建或更新 PR，以及发必要的 Issue/PR 评论。生产操作、正式合并和其他仓库的操作，仍按已有授权处理。

# #26 · Herdr 最小执行内核：裁剪可行性与跨平台原型验证

Source: https://github.com/xmxxc/workflow-core/issues/26

## What to build

验证能否从固定版本 Herdr 裁出由 WFC 项目独立维护的小型跨平台执行内核，让用户最终通过统一分发入口使用 WFC。交付源码依赖分析、隔离的可运行原型、实际规模与运行证据，以及是否值得正式接管的建议。

用户已授权本票调查和原型验证；正式迁移、移除 tmux 和公开发布在证据评审后另行决定。

## Source baseline

- Herdr 0.9.5，commit `ee5bfb5041bb3e4a49d591c72308aae3c81ecdde`：[固定源码](https://github.com/herdrdev/herdr/tree/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde)。
- 当前本机 Linux 完整二进制约 29 MiB；主 src 约 29 万行 Rust（含测试）。这不是裁剪结果，也不能外推 Windows 产物体积。
- 调查 portable-pty 本地补丁、Ghostty 终端解析和 Windows ConPTY/进程树的必要依赖。

## Scope

候选保留：PTY、进程启动/退出观察、终端文本读取、输入/中断/关闭、必要执行身份与恢复、最小本地通信。工作台 UI、复杂布局、远程连接、插件和通知先不纳入；无法分离的依赖必须如实说明。

WFC 继续拥有 dispatch、round/attempt、消息确认、owner fencing、故障路由和总控唤醒。角色策略、审查流程和工厂级留痕由上层负责。

## Acceptance criteria

- [ ] 在仓库提交可评审的裁剪方案：必要模块与传递依赖、不能删除的正确性机制、独立构建入口和维护范围。
- [ ] 建立上游来源清单：commit、取用文件、内容哈希、依赖版本、本地补丁、修改记录及相应许可证/署名。
- [ ] 隔离构建最小原型，明确是否脱离完整 Herdr 安装；报告实际源码规模、工具链、依赖、产物体积和完整 Herdr 对照。不可运行或不可分离也可作为有证据的结论。
- [ ] 经 WFC 执行契约与受控宿主跑通创建、观察、输入、完成回调、中断、关闭和进程清理；验证身份隔离、未知输入不重放，以及后端重启后的安全处理。
- [ ] 分别记录 Linux/原生 Windows 的构建与运行结果；交叉编译和受控宿主不替代真实宿主验收。无法执行的项目明确留待验证。
- [ ] 给出至少一次可执行平台上的真实宿主探针证据，并为另一平台提供复现步骤；保留报告、候选身份和失败诊断。
- [ ] 基于证据比较“裁剪后独立维护”与“固定完整 Herdr 随包分发”：安装体验、体积、兼容性、构建与长期维护成本。
- [ ] 经独立审查给出继续/停止建议和下一阶段规格、依赖票据；本票完成不自动启用新内核或移除旧后端。

## Blocked by

None（可从固定源码开始调查与隔离原型；PR #25 的用户审计与 Windows 复测独立推进，不作为研究硬依赖）。

## Delivery boundaries

- 保留 [PR #25](https://github.com/xmxxc/workflow-core/pull/25) 的修复候选，原型不得污染该候选。
- #9、#10 继续追踪既有 Herdr 适配与 Windows 实机验收。
- 当前不删除 tmux、不迁移已有 dispatch、不自动合并或发布；后端迁移需在正常闭环和关键异常恢复证据齐备后决定。
- 统一分发仍需明确宿主安装、路径和登录责任，不能把打包等同于解决全部环境问题。

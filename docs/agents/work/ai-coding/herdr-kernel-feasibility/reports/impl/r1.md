## Acceptance limits and remaining decisions

The evidence document has the criterion/result/limitation mapping requested by
the addendum, a full-versus-extracted comparison, native Windows reproduction
commands and draft dependent tickets.

Native Windows compile/runtime/package sizes are **unmeasured**: only Linux
target/runtime exists here, and no SDK license was accepted or SDK fetched.
The prototype's Windows branch does not provide job-tree ownership. Linux
evidence does not validate ConPTY, Windows process trees or native host argv.

Stdio is private, one connection, memory-only. Every mutation fences server
generation and unit nonce; restart loses all PTYs and does not replay input.
The lost acknowledgement test proves a once-applied old input is not silently
replayed. There is no same-generation request deduplication, reconnect,
reattach, bounded input/backpressure or durable service ownership.

Recommendation: **continue bounded kernel research, defer production takeover**.
Controller review should decide the lifecycle/loss contract first, then process
ownership on Linux and native Windows, then source/build trimming and native
authenticated host/WFC acceptance. A production WFC adapter is dependent work,
with its own approval; dispatch/attempt/owner/message/wakeup remain in WFC.
PR25 and issues #9/#10 remain independent.

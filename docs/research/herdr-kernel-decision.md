# #26：执行内核裁剪评审与下一阶段草案

状态：**供用户确认范围，尚未批准正式接管或迁移**。来源为 [#26](https://github.com/xmxxc/workflow-core/issues/26)，固定 Herdr 0.9.5 `ee5bfb5041bb3e4a49d591c72308aae3c81ecdde`。本文件综合[源码地图](herdr-kernel-source-map.md)和[隔离原型证据](herdr-kernel-prototype-evidence.md)；最终度量、命令退出码与源文件哈希以对应 evidence/artifacts 为准。

## 已回答和未回答的问题

可以脱离完整 Herdr 的 root package、server/TUI，独立构建一个真实 PTY + Ghostty 解析程序；这不是把 stdout 去色后充当终端。首轮 Linux stripped 产物 2,811,480 字节，对照完整 Herdr 30,285,672 字节。此对照有实际价值，但两者功能不同，不能当作等价性能或跨平台大小比较。

当前选取源码仍为 1,378 个文件、20,553,673 字节、429,124 行非空源码（含注释、vendor、内嵌测试等）；Rust normal/build 依赖闭包 Linux 为 41 个包、全目标为 61 个包（均含原型根包），还不包含 Zig/C 外部构建闭包。保留完整 Ghostty vendor 是确保首次实验可复现的选择，并非已经证明最小源集。图片、字体、渲染、开发资源及主题下载仍有残留成本。

受控宿主实际覆盖 PTY、终端读写/屏幕切换、resize、Ctrl-C、退出、普通进程组关闭、错误身份拒绝、服务代次变化与丢回执不重放；测试专用 WFC backend 使用现有 router 的 dispatch/round 和真实 done 回调。真实 OpenCode 1.19.5 的终端显示、Unicode 草稿、Ctrl-C 和关闭也已运行。后者没有执行已认证模型任务，不是完整真实 agent + WFC 回调闭环。

生命周期仍有关键缺口：逃逸 setsid 的后代、根进程先退出后的后代、服务 SIGKILL 后忽略 hangup 的子进程均出现存活。私有 stdio 原型没有重连、持久归属或活 PTY 恢复，输入/输出队列与关闭等待也没有生产级边界。Windows 构建、ConPTY、树清理及产物大小都未实测。上述缺口必须作为接管成本保留，不能通过改名为“轻量内核”省去。

## 建议

**继续一轮有边界的执行生命周期验证，暂缓正式接管。** 当前生产使用仍沿既有完整 Herdr 适配路径推进 #9/#10 和 PR #25 实机复测。固定版本随包分发是可比较的部署选项，不是本票自动批准的发布动作。

| 维度 | 独立裁剪内核 | 固定完整 Herdr 随包分发 |
| --- | --- | --- |
| 安装入口 | 可作为 WFC companion 随包；当前未实现分发 | 可保留现有 API 适配，打包固定二进制与平台依赖 |
| 实际 Linux 大小 | 首轮约 2.68 MiB | 对照约 28.88 MiB |
| 源码/供应链责任 | 自有服务 + patched PTY + Ghostty/Rust/Zig/C 闭包 | 跟踪固定上游及二进制/DLL 来源，复验 API 契约 |
| 维护能力 | 可独立演进窄契约，但需承担关闭、隔离、恢复与资源边界 | 更大功能表面，能够复用既有运行时；本实验没有重验其所有故障路径 |
| 兼容证据 | Linux 原语/受控回调/真实 TUI 探针；明确失败项 | 已有合同和用户 Windows 回传另见 #9/#10，不能视为所有功能已验 |
| Windows | 未构建/运行，直接 child kill 分支不足以保证树关闭 | 仍需保留 ConPTY 附加包、许可证与真实宿主验收 |
| 宿主配置 | 依然需要安装、绝对路径/runtime、登录/权限 | 同样需要；统一安装入口不解决这些责任 |

不建议以二进制缩小的比例作为正式接管依据。下一阶段应先验证我们愿意独立维护的生命周期合同，再决定继续裁剪或固定完整版本打包。若必须带回大量 App/layout/persist 结构才能满足恢复要求，停止该裁剪路线并报告成本。

## 待用户确认的最小规格

以下是候选合同，不是现有生产 API 或批准实施范围。

1. **边界。** 内核持有进程/PTY/VT、最小本地通信和执行身份；WFC 持有 dispatch、round/attempt、消息、owner、故障路由、唤醒。工作台、布局、远程、插件、通知不进入内核合同。
2. **生命周期。** create、inspect/read、literal input/keys、resize、interrupt、close 的结果需区分“拒绝且未执行”“已接受”“结果未知”；进程退出、PTY EOF、输出读错分开呈现。输入接受不代表宿主已执行。关闭有界，返回树清理已确认或仍未知的证据。
3. **归属与恢复。** 服务代次与实例 nonce 之外，需要平台可验证的进程创建身份/句柄。客户端断开重连、服务 crash、活 PTY 移交、宿主自身会话 resume 是不同合同。允许先把服务 crash 后状态定义为 lost/unknown，但必须说明是否保证后代清理、如何交给 WFC reconcile；不自动重派或重放输入。
4. **本地通信与资源。** 正式部署前选择单一必要入口；明确同用户端点权限、报文/输出/滚屏/并发上限、背压与取消。私有 stdio 实验不自动扩成完整终端服务。
5. **平台。** Linux 与原生 Windows 都需要自己的启动/关闭/后代/崩溃测试，Windows 明确系统或 app-local ConPTY、DLL 来源、进程树策略。交叉构建、Linux 代理和受控宿主不替代原生真实宿主。
6. **来源。** 固定上游 commit、逐文件哈希、Cargo.lock、Zig 包内容 hash、4 项 PTY/6 项 Ghostty 补丁、修改与移除条件；保留相应 LICENSE/NOTICE/署名。未经单独说明不改上游 vendor。分发前完成依赖 notice 与可复建源包检查。

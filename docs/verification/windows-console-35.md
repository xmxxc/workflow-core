## Observation, correlation and limits

The supervisor creates an unnamed outer Job Object with kill-on-close for containment and a named nested observation job. Each gated root is assigned to both through its retained Popen handle, with creation FILETIME checked before/after assignment. Descendants inherit membership without breakaway. The supervisor enumerates outer-job PID candidates, opens each process once, then verifies IsProcessInJob against the outer job, liveness and creation through that **same process handle** before querying image metadata. It retains the handle through publication. An outside-job replacement, exit, denied query or identity mismatch yields only a sanitized membership gap; no replacement image/creation is published. Cleanup addresses the outer job handle and exact root handles. Incompatible nested jobs fail closed.

The supervisor passes previously published metadata back into each fresh same-handle acquisition. A metadata-query error remains a gap unless that acquisition already verified exact job membership and matching known creation, then the same held handle becomes signaled and GetProcessTimes reaffirms the same creation after the error. This narrow outcome records `metadata_query_uncertain` with the original API/error and post-query state, followed by `owned_process_exited` with `proof: same_handle_signaled_after_metadata_query`; the exited item is not published as live. It does not establish that exit caused the API error or that the object was already exited at the query instant.

Live access denial, failed/unknown post-query wait or identity query, changed creation, and first-seen metadata failure remain gaps. Cached metadata is reused only to identify the precisely proved exited object, not to assume a live object's image query succeeded. The same proof path is consumed by observer acquisition without attaching; its existing retained-handle limit/lifetime stays unchanged. There is no blanket ignore of error 5, pin=None or a later observer exit report, and no new process monitor/polling loop. A subsequent unverifiable candidate still fails closed.

The console-free observer samples approximately every 10 ms plus API cost; membership publication is approximately every 20 ms plus API cost. A sample opens a noninherited QUERY-only handle to the exact nested observation job. A newly seen candidate is opened and checked for membership, liveness and the expected published creation identity through that same handle before reading image metadata. Successfully verified process handles remain open until the bounded observer exits, with at most 128 retained objects. The observer closes its observation-job query handle before window/console sampling; retaining process handles cannot keep outer kill-on-close containment alive.

For an unchanged cached publication, the observer queries the previously verified process object directly. WAIT_OBJECT_0 on that retained handle proves that owned object exited: record `owned_process_exited` with its known PID/creation and `proof: retained_handle_signaled`; do not reopen the PID or attach. If membership reports a definite nonmember after an earlier live wait, a second signaled-handle check can prove the intervening exit; failed membership queries remain unknown. Retained-handle exit proof also applies around console attachment. Cached live objects still require same-handle membership before observation. Changed publication identity, membership refusal and failed/unknown queries remain gaps and request STOP. A first unseen/unverified candidate has no retained ownership proof: absent PID, ERROR_INVALID_PARAMETER (87), and an exit during initial verification still fail closed; they are not classified as a verified owned exit.

Both EnumWindows callback liveness checks use the classified wait result. A failed/unknown wait before or after the visibility/owner check emits `window_identity_ambiguous` with the known candidate PID, fixed category/API/error code, and `check: before_visibility` or `after_visibility`. The observer sets STOP before persisting this event and before subsequent console queries; later successful association cannot clear it. After observer shutdown/cleanup, the supervisor rechecks a pending STOP marker before accepting phase completion, so a late propagated failure remains incomplete without masking observer/watchdog errors. A signaled retained object remains `owned_process_exited`. Empty enumeration, a foreign owner, an invisible window or a vanished window alone does not become a failed liveness query.

Gap records contain a fixed category, API name and nullable numeric Win32 error code. Candidate PID is included for an already published or previously known-owned identity; no foreign image, replacement creation identity, title, argv or environment is recorded. Query failure and ownership refusal are distinct from exact retained-handle exit. AttachConsole failure and console membership-query failure also retain fixed API/error categories; unavailable association remains measurement uncertainty, not proof of no window.

AttachConsole/GetConsoleWindow/GetConsoleProcessList associate a console window with the pinned subject; GetWindowThreadProcessId supplies its owner. An external conhost/OpenConsole is queried only by direct association and is never adopted for cleanup or inferred to be a subject's child. No console input/control events are sent; the observer detaches itself immediately. Window and attachment authorization never depend on a PID-list entry alone.

The watchdog owns a separate noninherited duplicate of the outer job handle, released only by its thread after callback completion. Cancellation and callback admission share a short lock. Cancellation fences a stop-reason check already in progress; callbacks admitted earlier retain their own valid handle until finished. The supervisor cancels and joins before selecting a successful report. If the one-second join expires, it records `watchdog_shutdown_unresolved`, terminates/reaps the owned job with its original handle, and returns nonzero. An admitted callback may still be in progress in that unresolved case; its duplicate stays valid and is closed by the thread or by supervisor process exit. A callback/release error also forces nonzero. These error outcomes cannot be relabeled completed; `observer_returncode`, `watchdog_shutdown` and `watchdog_outcome` preserve the available evidence.

Collect only `events-*.jsonl` after `supervisor_end` with `cleanup: owned_job_empty`. Merge records by `monotonic_ns`; use `utc_ns` only for approximate human timestamps. Each record includes its writer PID/creation identity. Distinct observer sample states are deduplicated; event counts are not flash counts or exact durations. `phase_begin`/`phase_end`, stage labels, `queue_launch`, `rpc_result`, `detached_relay` and process events delimit the active phase. Match a window on HWND **and** owner PID/creation identity. HWND or PID alone is reusable. Parent metadata is labeled `parent_candidate`: a contemporaneous process-snapshot parent that is itself a current verified job member and no younger than the child. It is not a historical parent proof. An unavailable/exited/outside-job parent remains unknown.

False negatives and perturbations must accompany every result:

- A child or window can appear/disappear between polls. Missing process identity/membership is recorded as `membership_identity_gap` and ends the capture as incomplete. An exit before local ownership verification can still stop this conservative probe. A proven exit of a retained, already verified object is recorded separately and cannot authorize replacement observation. Missing console association is recorded, not treated as absence of a window. There is no lossless process/window lifecycle trace.
- GetConsoleWindow in a pseudoconsole can return a message-only, locally invisible HWND. Its API association does not identify the visible Windows Terminal surface. OpenConsole/terminal UI may be external or inaccessible; do not infer its owner/parent from timing or process names. If the visible surface cannot be associated, stop with **UNRESOLVED** ownership.
- A visible-window style flag is not proof a human saw a flash; compositor timing, occlusion, other desktops, integrity levels and user sessions affect visibility. A selftest on another desktop/session does not calibrate this run.
- AttachConsole is an active observation: it can extend console lifetime and changes observer attachment. Server response and queue-fixture sleeps widen visibility. These fixtures can prove a launch/observation mechanism exists, not the original flash frequency or the actual executable's behavior.
- Observer/wrapper consoles are deliberately suppressed with CREATE_NO_WINDOW. Subject launch options and real source helper/queue options are preserved as stated above. Additional wrapper ancestry and Job Object containment can change behavior; compare phase metadata, not overall console count.
- Source flags alone, a quiet fixture, a subprocess return code, or a missing HWND cannot establish root cause or a quiet same-path retest. The RPC stage does not cover Herdr's own server/PTY startup; queue fixture does not cover actual codex.exe descendants.

If this cannot attribute a transient conhost/OpenConsole surface safely, the missing signal is a lossless native process/window lifecycle trace and reliable terminal-surface association on that isolated desktop.
